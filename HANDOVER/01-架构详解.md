# 01 · 架构详解

## 分层：Feature-First + Clean Architecture

```
presentation  ──────→  domain  ←──────  data
   （页面/Provider）   （纯模型）      （SQLite CRUD）
```

**铁律（打破就是埋 bug）**：

- `domain/` **禁止 import `package:flutter/*`**，也禁止 import `data/`
- `data/` 可以 import `domain/`，不能 import `presentation/`
- `presentation/` 可以 import `domain/` 和 `data/`

这样做的收益：业务规则（农历换算、循环判定、日期解析）能脱离 UI 单测，
将来换存储或换框架不用重写业务逻辑。`core/lunar/lunar_engine.dart` 就是典型——
它不依赖任何 Flutter 东西，`test/lunar_engine_test.dart` 直接裸测。

## 目录结构逐个说明

### `lib/main.dart` —— 启动流程

顺序**不能改**，每一步都有原因：

```dart
WidgetsFlutterBinding.ensureInitialized();
final storage = await SuiyaStorage.open();          // 1. SharedPreferences
final repository = await SqfliteMemoryRepository.open();  // 2. 开 SQLite + 跑迁移
LogService.attach(repository.db);                   // 3. 日志落库要先于任何业务日志

// 4. 加载自定义节日 —— 必须在读「勾选了哪些日子」之前
final customs = await _loadCustoms(repository.db);
SuiyaStorage.registerKnownIds(customs.map((c) => c.id));   // 4a. 注册 custom_* id

// 5. 绑定节日解析器（三层顺序：内置 → 节气 → 自定义）
MemoryRecord.bindFestivalResolver((id, year) {
  final builtin = Festivals.byId(id);
  if (builtin != null) return builtin.dateIn(year);
  for (final t in Festivals.allTerms()) {             // 二十四节气
    if (t.id == id) return t.dateIn(year);
  }
  for (final c in customs) {                         // 自定义节日
    if (c.id == id) return c.dateIn(year);
  }
  return null;
});

// 6. 媒体目录预热 / 提醒服务初始化 / 日志
runApp(ProviderScope(overrides: [
  storageProvider.overrideWithValue(storage),
  memoryRepositoryProvider.overrideWithValue(repository),
  databaseProvider.overrideWithValue(repository.db),
  customFestivalsSnapshotProvider.overrideWithValue(customs),  // 启动快照
], child: const SuiyaApp()));
```

**为什么有启动快照**：`customFestivalsSnapshotProvider` 存的是 `main()` 读出来的那份数据。
好处有两个 —— 首帧不用再查一次库；resolver 和 timeline 看到的是同一份数据，不会出现
「时间轴有节日但日期算不出」的不一致。
**代价**：新增/删除自定义节日后必须**回写快照**（见 `CustomFestivalActions`）。

provider 集中管理在 `features/record/presentation/record_providers.dart`（438 行）。

### 操作型（`Provider<XxxActions>`）

`RecordActions` / `PlaceActions` / `CustomFestivalActions` / `PresetActions`

模式统一：执行写库 → `ref.invalidate()` 精确刷新受影响的 provider → 写日志。
`CustomFestivalActions` 额外要**回写启动快照 + 重新注册已知 id**。

### 状态容器

`selectionProvider`（`StateNotifierProvider<FestivalSelection>`）——
记录用户勾选了哪些节日。变更时会 invalidate `timelineProvider(今年)`。

### 关键 helper

```dart
/// 计算某节日在 year 年的公历日期；不适用返回 null
LunarDateTime? resolveDateIn(String id, int year,
    List<CustomFestival> customs, Festival? resolved) {
  if (id.startsWith('custom_')) {
    final c = _customById(customs, id);
    if (c != null) return c.dateIn(year);   // ← 走 CustomFestival.dateIn，带 anchorYear 约束
  }
  return resolved?.dateIn(year);
}
```

**全项目凡是要算节日日期的地方，都必须走这个函数。**
直接用 `asFestival().dateIn(year)` 会丢掉 `anchorYear` 约束，
「仅此一次」的日子会在每个年份都冒出来 —— v1.4.0 的真实 bug。

## 数据流：编辑一条记录

```
用户点「记此刻」
  → context.push(Routes.recordNew, extra: festival)
  → RecordEditorPage(festival: xxx)
  → _resolveFestival(id) 拿内置节日 prompts
  → 若是 custom_*，Future.microtask 调 _loadCustomPrompts(id) 异步补 setState
  → 用户填写文字/图片/问答
  → ref.read(recordActionsProvider).save(record)
  → MemoryRepository.save() → sqflite upsert
  → invalidate(recordsOfYearProvider) / timelineProvider / yearReviewProvider
  → LogService.info(...)
  → context.pop() 回到时间轴，UI 自动刷新
```

编辑已有记录时，`_loadCustomPrompts` 会**保留用户已填的答案**：
先用 `existing.qa` 建 `question → answer` 映射，再套用新 prompts。

## 通知链路

```
保存记录 → ReminderService.scheduleFor(record, advanceDays: n)
  → 算出 fireAt = 节日日期 - n 天
  → flutter_local_notifications.zonedSchedule()
  → Android NotificationManager 持久化（重启不丢）
```

Android 13+ 需要 `POST_NOTIFICATIONS` 运行时权限，
`ReminderService.requestPermission()` 负责申请。
`getNotificationAppLaunchDetails()` 用于「点通知进 App 后跳到对应记录」。
