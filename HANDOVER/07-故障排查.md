# 07 · 故障排查

## 🔴 当前阻塞：Windows 管道句柄耗尽

### 现象

```
CreateFile failed 231 (所有的管道范例都在使用中。)
ProcessException: 所有的管道范例都在使用中。
  Command: ...\dartaotruntime.exe ...\analysis_server_aot.dart.snapshot ...
```

`dart analyze` / `flutter analyze` / `flutter build` **全部失败**。

### 根因

`dart analyze` 会派生子进程（analysis server），通过**匿名管道**通信。
Windows 上管道句柄耗尽时，创建子进程直接失败。

**这不是代码问题。** 验证方式：
- `dart --version` 正常（不派生进程）
- 写个最小程序调 `Process.start('cmd.exe', ['/c','echo','hi'])` 同样失败
- 关掉沙箱重试一样失败

### 已尝试且**无效**的方案

| 尝试 | 结果 |
|---|---|
| 去掉管道重定向 `\| tail` | ✗ |
| 加 `--no-version-check --no-pub` | ✗ |
| 直接调 `dart analyze lib`（不经 flutter） | ✗ |
| 关沙箱执行（`dangerouslyDisableSandbox`） | ✗ |
| 换 PowerShell 工具执行 | ✗ |
| 输出重定向到文件 | ✗ |
| 等 20 秒后重试 | ✗ |
| 检查进程数（369 个，无 dart 残留） | 无泄漏进程 |

### 建议的解法（按推荐顺序）

1. **重启 Windows** —— 最直接，大概率一次解决
2. **注销/重新登录** —— 比重启轻，通常也能释放句柄
3. **关闭大量占用句柄的程序**：
   Chrome（42 个进程）、msedgewebview2（20 个）、svchost（100 个）。
   关掉 Chrome 试试，尤其关掉所有扩展和 DevTools 窗口
4. **等** —— 有时是某个短生命周期进程泄漏，几十秒后自动恢复
5. **绕过 analyzer，直接跑测试**：`flutter test` 也派生进程，可能同样受阻，
   但 `dartaotruntime.exe --version` 能跑说明运行时本身没坏
6. **用 IDE 代替命令行**：VS Code / Android Studio 内置的分析器走的是长连接
   analysis server，不受这个瞬时限制影响

### 恢复后的验证

```bat
cd /d D:\suiya_build\suiya
set PUB_CACHE=D:/suiya_build/pub-cache
set CI=true
D:\flutter_sdk\flutter\bin\cache\dart-sdk\bin\dart.EXE analyze lib
```

## 其他已知环境问题

### GitHub 不通

`github.com` / `api.github.com` / `raw.githubusercontent.com` 全部返回 000。

- 用加速镜像：`https://ghfast.top/<原github_url>`
- `git clone` 会被 schannel 吊销检查拦截，**不要走 git**，直接 curl 镜像 zip
- 例子：`curl -x http://127.0.0.1:7897 -o out.zip "https://ghfast.top/https://github.com/xxx/yyy/archive/refs/heads/main.zip"`
  （完整路径、末尾带 `.zip`、**不要加 `-L`**）

### gradle 仓库不通

`dl.google.com` / `services.gradle.org` 不通。
用 `maven.aliyun.com/repository/{google,public,gradle-plugin}`。

### 代理会让 Gradle 挂住

构建时如果继承了系统代理会卡死。
`build_ci.bat` 里显式清空 6 个变量：

```bat
set http_proxy=
set https_proxy=
set HTTP_PROXY=
set HTTPS_PROXY=
set all_proxy=
set ALL_PROXY=
```

### 目录删不掉（WorkBuddy 特有）

工作区目录被文件监视器持有句柄，`rmdir` / `rm -rf` 报
"Device or resource busy" 或 "另一个程序正在使用此文件"。

**解法**：先把内容（`shopt -s dotglob` 含隐藏项）`mv` 到 `%TEMP%` 下的暂存区，
顶层空目录留着（重启 WorkBuddy 后释放）。系统回收站 API 在本环境也受限，
`mv` 到 Temp 是最可靠的方式。

### PowerShell 输出被吞

`Write-Output` / `Get-Process` 的结果在某些调用路径下不显示。
**解法**：改用 `*> 'C:\path\file.log'` 重定向，再用 Bash 读文件。
注意 PowerShell 5.1 不支持 `&&`、`??`、`?.` 等 PowerShell 7 语法。

## 常见代码层问题速查

### 路由点了没反应

**症状**：点某个入口，界面不动。

**原因**：用了 `Navigator.pushNamed`，go_router 接管了根 Navigator，裸调用会静默失败。

**解法**：改用 `context.go('/path')`（切栈）或 `context.push('/path', extra: data)`（压栈）。
路由必须先在 `lib/app/router.dart` 的 `buildRouter()` 里声明。

### 节日日期显示 null

**症状**：记录/时间轴上某个节日没有日期，或剩余天数为空。

**原因**：resolver 没覆盖这个节日类型。早期版本只查 `Festivals.byId`，
漏掉二十四节气和自定义节日。

**排查**：
1. 检查 `main.dart` 的 `bindFestivalResolver` 是不是三层顺序
2. 检查计算日期的地方是不是走了 `resolveDateIn()`
3. `custom_*` id 有没有在 `SuiyaStorage.registerKnownIds()` 注册

### 重启后自定义节日消失

**症状**：勾选了自定义节日，杀进程重启后变成未勾选。

**原因**：`SuiyaStorage._festivalExists()` 不认识 `custom_*` id，
读 SharedPreferences 时把它们当脏数据过滤掉了。

**解法**：`main()` 里在读 SharedPreferences **之前**调
`SuiyaStorage.registerKnownIds(customs.map((c) => c.id))`。

### 新增的自定义节日不出现

**症状**：保存成功，列表里有，但时间轴/节日选择页没有。

**原因**：`customFestivalsSnapshotProvider` 启动快照把新数据「冻」住了。

**解法**：`CustomFestivalActions.save/delete` 里回写快照：

```dart
final next = await _store.all();
_ref.read(customFestivalsSnapshotProvider.notifier).state = next;
SuiyaStorage.registerKnownIds(next.map((c) => c.id));
await _afterChange();   // invalidate timeline / yearReview
```

### 「仅此一次」每年都出现

见 `04-业务规则.md` 的专门章节。核心是
**`asFestival()` 不带年份，真实日期必须走 `CustomFestival.dateIn(year)`**。

### 编辑记录时提示词不对

**症状**：编辑自定义节日的记录，看到的是通用问题，或答案错位。

**原因**：`_resolveFestival()` 只查内置和节气，自定义节日返回 null 就回退了。

**解法**：`_loadCustomPrompts(id)` 异步补，注意保留 `existing.qa` 里已填的答案。

### DB 迁移后数据丢失/报错

**排查**：
1. `schema.dart` 的 `version` 加了吗
2. `migrate()` 里有对应 `if (from < N && to >= N)` 分支吗
3. `ALTER TABLE` 前用 `PRAGMA table_info` 检查列存在了吗（幂等）
4. 历史数据回填的 SQL 对不对（注意时区：`created_at / 1000, 'unixepoch', 'localtime'`）

### `Iterable.firstOrNull` 编译不过

Dart SDK 3.13.5 未必提供这个扩展。**改用显式 for 循环查找。**

```dart
// ✗
final c = customs.where((e) => e.id == id).firstOrNull;
// ✓
CustomFestival? c;
for (final e in customs) { if (e.id == id) { c = e; break; } }
```

### `analyzer` 报 231 但代码没问题

见本文最上面的章节，是环境问题。
