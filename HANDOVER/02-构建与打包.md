## 国内镜像（必须设，否则依赖下载会卡死）

```bat
set PUB_HOSTED_URL=https://pub.flutter-io.cn
set FLUTTER_STORAGE_BASE_URL=https://storage.flutter-io.cn
```

Gradle 侧可用仓库（在 `settings.gradle.kts`）：
`maven.aliyun.com/repository/{google,public,gradle-plugin}`、
`mirrors.cloud.tencent.com/gradle/`。

**不通的域名**：`dl.google.com`、`services.gradle.org`。
**注意**：构建时如果继承了系统代理（`http_proxy` 等），会导致 Gradle 挂住。
本项目的 `build_ci.bat` 里显式把 6 个代理变量清空。

## 标准命令

```bat
:: ── 依赖 ──
set PUB_CACHE=D:/suiya_build/pub-cache
set PUB_HOSTED_URL=https://pub.flutter-io.cn
set FLUTTER_STORAGE_BASE_URL=https://storage.flutter-io.cn
cd /d D:\suiya_build\suiya
D:\flutter_sdk\flutter\bin\flutter.bat pub get

:: ── 静态分析（优先用这个，比 flutter analyze 少一层启动开销）──
D:\flutter_sdk\flutter\bin\cache\dart-sdk\bin\dart.EXE analyze lib

:: ── 只看 error（CI 门禁用）──
D:\flutter_sdk\flutter\bin\cache\dart-sdk\bin\dart.EXE analyze lib --fatal-infos

:: ── 测试 ──
D:\flutter_sdk\flutter\bin\flutter.bat test
D:\flutter_sdk\flutter\bin\flutter.bat test test/lunar_engine_test.dart   :: 单文件

:: ── 构建 ──
D:\flutter_sdk\flutter\bin\flutter.bat build apk --release
D:\flutter_sdk\flutter\bin\flutter.bat build apk --debug     :: 快，用于自测

:: ── 装机 ──
C:\Users\XX\.workbuddy\binaries\android-sdk\platform-tools\adb.exe install -r build\app\outputs\flutter-apk\app-release.apk

:: ── 看日志 ──
C:\Users\XX\.workbuddy\binaries\android-sdk\platform-tools\adb.exe logcat -s flutter:* ActivityManager:E AndroidRuntime:E
```

> `flutter` 在 `bin` 目录下是 `flutter.bat`（不是 `flutter.exe`）。
> 直接调 `dart.exe` 做分析可以绕开 flutter 工具的启动脚本层，更稳定。

## 打包铁律（用户明确要求）

> **每次打包交付前，必须先升级版本号。**

三处同步改，缺一处真机上显示就会错：

| 文件 | 字段 | 当前值 |
|---|---|---|
| `pubspec.yaml` | `version:` | `1.5.1+13` |
| `android/local.properties` | `flutter.versionName` | `1.5.1` |
| `android/local.properties` | `flutter.versionCode` | `13` |
| `lib/features/backup/presentation/settings_page.dart` | 关于页文本 | `岁忆 v1.5.1` |

`pubspec.yaml` 的 `+9` 是 build number，**每次打包 +1**。
语义版本（`1.4.1`）按改动大小决定是否递增。

## 交付前校验

```bat
:: 用 aapt 确认实际打进包里的版本号（别信 pubspec，要验产物）
C:\Users\XX\.workbuddy\binaries\android-sdk\build-tools\35.0.0\aapt.exe dump badging build\app\outputs\flutter-apk\app-release.apk | findstr version
```

期望输出类似：
```
package: name='com.suiya.suiya' versionCode='13' versionName='1.5.1'
```

> **产物有两个位置**：
> `build\app\outputs\flutter-apk\app-release.apk`（flutter 工具固定名副本）和
> `build\app\outputs\apk\release\suiya-v1.5.1+13.apk`（`applicationVariants` 改名后的正式产物，**交付用这个**）。

## 项目内的构建脚本

根目录有三个 `.bat`，都是历史遗留，**环境变量指向 C 盘旧路径，已过时**：

| 文件 | 状态 |
|---|---|
| `build_ci.bat` | 过时，指向 `C:\build\suiya` 和 C 盘 SDK |
| `run_build.bat` | 过时，包装 `build_ci.bat` |
| `build_android.bat` | 过时，且只 build debug |

**不要用它们。** 直接按上面「标准命令」手敲，或新建一个指向 D 盘的脚本。
如果想清理，这三个文件可以删（记得 `.gitignore` 已忽略 `*.log`）。
