# 04 · 业务规则

## 循环类型：两套 enum，别搞混

项目里有两个循环类型 enum，**用途不同**：

### `RecurrenceType`（`core/festival/festival.dart`）—— 节日库用

```dart
enum RecurrenceType {
  solarOnce,     // 公历固定单次（结婚纪念日）
  solarAnnual,   // 公历年度循环（母亲生日 3/20）
  lunarAnnual,   // 农历年度循环（春节、中秋、端午）
  lunarMonthly,  // 农历每月固定日（初一、十五、廿三祭灶）
  solarTerm,     // 节气（清明、冬至）
}
```

### `Recurrence`（`record/domain/memory_record.dart`）—— 记录用

```dart
enum Recurrence {
  solarAnnual, solarFixed, lunarAnnual,
  lunarMonthly, solarTerm, once,
}
```

记录侧的循环**与节日库共用同一套判定**，保证「手账节点」和「节日节点」算法一致。
所以两边有对应关系，改动时要同步考虑。

## `solarOnce` 的坑（v1.4.0 真实 bug，重点看）

### 现象

用户在自定义节日里选「仅此一次」，选了 2026 年。结果**之后每年都出现**。

### 根因

`RecurrenceType.solarOnce` 在 `Festival.dateIn()` 里和 `solarAnnual` **共用同一个分支**，
每年按传入的 `year` 重新算一遍。对「公历固定日」是对的，对「仅此一次」是错的。

### 修法（v3 已完成）

1. **加列**：`custom_festivals.anchor_year INTEGER`，历史数据用 `created_at` 的年份回填
2. **模型层**：`CustomFestival` 加 `anchorYear` 字段 + `effectiveAnchorYear` getter
3. **日期层**：`dateIn()` 对非锚定年份返回 `null`

```dart
/// 「仅此一次」的锚定年份；其他循环类型为 null
final int? anchorYear;

/// 一次性日子实际生效的年份：用户选的年份，未选则退回创建年份
int get effectiveAnchorYear =>
    anchorYear ?? _yearOf(createdAt) ?? DateTime.now().year;

/// [asFestival] 不带年份信息，仅供列表分类与提示词使用。
/// 计算真实日期一律走 [dateIn]，否则「仅此一次」会被当成每年重复。
Festival asFestival() { ... }

/// 该节日在 [year] 年的公历日期；不适用时返回 null
LunarDateTime? dateIn(int year) {
  if (isOnceOnly && year != effectiveAnchorYear) return null;
  return asFestival().dateIn(year);
}

/// 是否在 [year] 年出现
bool occursIn(int year) => !isOnceOnly || year == effectiveAnchorYear;
```

4. **调用层**：时间轴、年度回望、resolver 全部改用 `resolveDateIn()` 统一 helper
5. **UI 层**：编辑页在 `solarOnce` 时显示年份选择器（2000-2099）

### 写代码时的铁律

> **凡是要算节日真实日期的地方，一律调 `resolveDateIn()`。**
> 永远不要直接 `customFestival.asFestival().dateIn(year)`。

`asFestival()` 存在的意义是「把它当成一个普通 Festival 用于分类、图标、提示词」，
它**故意不携带年份信息**。拿它算日期就是 bug 的源头。

`copyWith()` 里也处理了这个约束：

```dart
anchorYear: (recurrence ?? this.recurrence) == CustomRecurrence.solarOnce
    ? (anchorYear ?? this.anchorYear)
    : null,   // 非一次性循环显式清掉，避免留下脏数据
```


## 节日解析器的三层顺序

`main.dart` 里绑定的 resolver 必须按这个顺序：

```dart
MemoryRecord.bindFestivalResolver((id, year) {
  final builtin = Festivals.byId(id);
  if (builtin != null) return builtin.dateIn(year);          // ① 内置
  for (final t in Festivals.allTerms()) {
    if (t.id == id) return t.dateIn(year);                   // ② 二十四节气
  }
  for (final c in customs) {
    if (c.id == id) return c.dateIn(year);                   // ③ 自定义
  }
  return null;
});
```

顺序不能乱。历史 bug：早期版本只查 `Festivals.byId`，导致
**二十四节气、自定义节日的 `displayDate` / `daysUntil` / 提醒时间全是 null**。

## 提问模板（prompts）

节日和自定义节日都可以带一组「引导问题」，用户填记录时看到的是结构化问答而不是空白文本框。

- 内置节日 / 节气：`festival.prompts`（`Festival` 模型自带）
- 自定义节日：`customFestival.prompts`（存在 `prompts_json` 列）

**已知问题（v1.4.0 已修）**：
编辑已有自定义节日记录时，`RecordEditorPage._resolveFestival()` 只查内置和节气，
自定义节日返回 `null`，回退到通用提问，**用户填的答案对不上问题**。

修法是新增 `_loadCustomPrompts(id)` 异步加载：

```dart
Future<void> _loadCustomPrompts(String id) async {
  if (!id.startsWith('custom_')) return;
  final customs = await ref.read(customFestivalsProvider.future);
  final matched = /* 按 id 查找 */;
  if (matched == null || matched.prompts.isEmpty) return;
  setState(() {
    _prompts = matched.asFestival().prompts;
    for (final q in prompts) {
      _qaCtl[q.question] ??=
          TextEditingController(text: answered[q.question] ?? '');  // 保留已填答案
    }
  });
}
```

注意 `initState` 是同步的，自定义集合在 provider 里，所以先返回内置结果，
拿到后再 `setState` 替换。这个「同步壳 + 异步补」的模式在别处也会遇到。
